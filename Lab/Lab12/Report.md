### Задание 3. Структура Laravel

**Ответ:**  
- `app/` — основной код приложения: контроллеры, модели, политики, middleware.  
- `routes/` — описание маршрутов приложения.  
- `resources/views/` — Blade-шаблоны интерфейса.  
- `database/` — миграции, сидеры и фабрики для базы данных.  
- `public/` — публичная директория, которая доступна веб-серверу и содержит `index.php` как единую точку входа.

Document root nginx должен указывать на `public/`, потому что только эта папка предназначена для прямого доступа из браузера. Если указать на `/var/www/boardy/`, наружу могут стать доступны `.env`, `vendor/`, исходный код приложения и другие служебные файлы, что является серьёзной угрозой безопасности.

### Задание 4. Nginx-конфиг
![04-nginx-config.png](screenshots/04-nginx-config.png)

![05-laravel-welcome.png](screenshots/05-laravel-welcome.png)

**Ответ:**  
`try_files $uri $uri/ /index.php?$query_string` заставляет nginx сначала искать реальный файл по URL, потом директорию, а если ничего не найдено — передавать запрос в `index.php` Laravel вместе с параметрами строки запроса. Это нужно для «красивых» маршрутов, где URL не соответствует имени физического файла.

Без этой строки переход на `/posts/3` закончится ошибкой 404 на уровне nginx, потому что файла или папки `/posts/3` на диске нет. Laravel даже не получит запрос и не сможет обработать маршрут через роутер.

### Задание 14. Policy и редактирование
![17-edit-own.png](screenshots/17-edit-own.png)

![18-edit-foreign-403.png](screenshots/18-edit-foreign-403.png)

**Ответ:**  
В Lab10–11 на чистом PHP проверка прав делалась вручную: нужно было в каждом обработчике получать текущего пользователя, загружать запись из базы, сравнивать `user_id` автора с `$_SESSION['user_id']`, а потом самостоятельно возвращать 403 или делать редирект. Это означало дублирование одной и той же логики в нескольких файлах.

В Laravel Policy выносит правило доступа в отдельный класс, а в контроллере остаётся одна строка `$this->authorize(...)`. На тот же эффект уходит в несколько раз меньше кода: вместо десятков строк ручных проверок в разных местах мы получаем компактный класс политики и декларативную проверку в контроллере и Blade через `@can`.

Сократилось именно количество ручного кода интеграции и сетевой логики за счёт готового фреймворочного решения.

## Часть E. Архитектурные вопросы

### Задание 22. Что осталось от прошлых практик

**Ответ:**  
`/var/www/boardy-legacy/` и старая БД `boardy` не удалены, потому что это рабочее наследие прошлых лабораторных и точка сравнения с новой реализацией на Laravel. Они нужны как резервная копия, как исторический артефакт и как база для следующих этапов курса, где legacy-компоненты ещё используются.

Если попробовать открыть `https://kilqa.ai-info.ru/login.php`, старый PHP-логин не откроется. Главный домен теперь обслуживается Laravel через `public/index.php`, а nginx больше не смотрит в старую директорию, поэтому запроса к `login.php` в legacy-проекте просто не происходит.

### Задание 23. FastAPI и React

**Ответ:**  
Сейчас FastAPI и React не используются внутри Laravel-проекта, потому что в этой лабораторной главная цель — полностью перевести основной домен на Blade, Eloquent, Breeze и Socialite. Если сразу смешивать Laravel, старый React и FastAPI, то архитектура снова станет переходной и запутает основную идею переезда на фреймворк.

Кроме того, на текущем этапе Laravel умеет сам обслуживать страницы, авторизацию и CRUD без промежуточного API-слоя. FastAPI и React пригодятся в Lab13, когда Laravel станет OAuth Authorization Server через Passport, FastAPI начнёт валидировать Bearer-токены, а React вернётся как фронтенд для работы через новый API-слой.

### Задание 24. Реалтайм

**Ответ:**  
Чтобы комментарии появлялись без F5, нужно событийное realtime-решение: сервер должен публиковать событие о новом комментарии, а клиенты — получать его по постоянному соединению. Обычно для этого используют WebSocket-инфраструктуру и брокер сообщений или очередь, чтобы изменение на сервере мгновенно доходило до всех подписанных клиентов.

Два главных кандидата в рамках нашего проекта — Laravel и FastAPI. Laravel подходит как источник доменных событий, потому что именно он теперь владеет постами, комментариями и авторизацией; FastAPI подходит как отдельный API/BFF-слой, через который удобно проксировать realtime-взаимодействие и клиентские запросы. В следующих лабораторных эта схема дополняется Redis и WebSocket-механизмом.
